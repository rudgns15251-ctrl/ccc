## 1. 현재 CAP의 핵심 강점

1. **"반응한다 ≠ 격리할 수 없다"라는 추론 축** [사실·DRAFT 기획]. v0.2는 단발 반응, 지속 노출, 복합 자극을 구분합니다. 같은 장르 게임이 흔히 쓰는 "약점 하나 찾기"보다 한 단계 깊은 구조입니다. [평가] 퍼즐로 다듬기 가장 좋은 재료입니다.
2. **지연 판정과 SUCCESS/FAILURE/실제 탈출의 분리** [IMPLEMENTED]. 승인 순간에 정답을 알려주지 않습니다. ROOM A처럼 "실패했지만 탈출은 없음"을 따로 표현할 수 있습니다. 공포 장르에서 드문 **불확실성의 시간**을 시스템으로 갖추고 있습니다.
3. **비상방송이 시설 조작이 아니라 "사람에게 하는 말"** [IMPLEMENTED·APPROVED]. 작성, 검토, 송출 승인을 단계로 나누고, 송출 후 잠급니다. 플레이어의 책임감을 만드는 장치로 훌륭합니다.
4. **사망·부상 UNKNOWN과 0명의 구분** [IMPLEMENTED]. "확인되지 않음"을 정직하게 기록하는 관료 문서 톤은 이 시대 배경과 잘 맞습니다.
5. **사고 뒤 정확한 업무 복귀** [IMPLEMENTED]. 사고가 끝나면 같은 Runtime, Focus, Scroll로 돌아옵니다. "아무 일 없던 것처럼 돌아가는 일상"이라는 공포 연출의 기반이 이미 있습니다.
6. **기록 계층의 분리** [IMPLEMENTED]. Research Log, Archive, Hypothesis, 사고보고서, Story Record가 서로 다른 의미로 존재합니다. 정정, 오판, 검열을 서사 도구로 쓸 토대입니다.
7. **T04 개체 콘셉트** [DRAFT]. 공격성이 아니라 "탐색이 사람을 구조물처럼 붙잡는다"는 피해 양상은 새롭고 설득력 있습니다.

## 4. Core Loop 개선안

현재 루프는 Profile → CCTV → 실험 → 격리 → 지연 → (Incident → 방송 → 결과) [IMPLEMENTED]입니다. 구조 자체는 좋습니다. 문제는 **각 단계의 정보 역할이 겹친다**는 점입니다.

### 4-1. 정보 역할 재배분 원칙 [제안 · A]
| 단계 | 역할 | 주지 말아야 할 것 |
|---|---|---|
| Profile | 외형, 과거 사고, **틀린 가설을 포함한** 이전 소견 | 현재 정답 조건 |
| CCTV | 일상 환경에서의 **단발 반응**만. 원인을 단정하지 않는 관찰 | 실험 결과 수준의 비교, 메타 안내문 |
| 실험 | **조건을 통제한 비교**(지속, 복합, 감소), 수치가 있는 결과 | Profile/CCTV의 반복 |
| 격리 후보 | 측정 가능한 **속성 값**(조도, 외부 차음, 잔향 시간) | "~를 구분해 줄이는 구성" 같은 평가형 문장 |
| 지연 결과 | 선택의 결과를 **관찰로** 전달 | 점수, 정답 표시 |

- 기대 경험: "CCTV만으로는 어두운 방(B)이 맞아 보인다 → 실험으로 반향 문제를 확인해야 C에 도달한다"라는 **발견**.
- 충돌: T04 설정 변경이 아니라 **기존 사실의 배치 변경**입니다. 다만 텍스트 수정이므로 사용자 승인이 필요합니다.

### 4-2. 실험 3회 제한을 의미 있게 [제안 · A]
- 실험 결과에 **비교 가능한 값**을 넣습니다. 예: "접촉 지속 — 단발 4초 / 잔향 22초", "회복 시간 — 1분 미만 / 6분".
  - 근거: 현재 결과는 정성 문장뿐이라 CCTV 문장과 차이가 없습니다.
  - 참고 원리: Papers, Please의 값 대조.
- 격리 후보의 속성 값과 이 수치가 **연결**되게 합니다. 예: ROOM B 잔향 시간 2.1초, ROOM C 0.4초.
- 기대 경험: 실험을 고르는 이유가 생깁니다. ECHO를 건너뛰면 B와 C를 확신하기 어렵습니다.
- 공정성 안전망은 v0.2 원칙("관련 없는 실험을 골라도 핵심 정보를 전부 잃지 않음")을 유지하되, 확신 대신 **위험한 추측**이 되게 합니다. ARCHIVE_03 정정 문서가 보조 단서 역할을 합니다.

### 4-3. 실패 뒤 계속할 동기 [제안]
- **A안 (A~B):** 사고보고서와 과거 결과를 다음 Case 문서에 **인용**합니다. 예: 다음 개체 Profile의 관리 권고에 "T04 사고 이후 금속 점검 도구 사용 제한" 한 줄. 기존 Historical Facts / Campaign Fact Query [IMPLEMENTED]로 조건부 텍스트를 만들 수 있다면 C, 아니면 고정 텍스트 A.
- **B안 (C):** 사고가 Campaign 수준의 **시설 상태 메모**(폐쇄 구역, 결원 표시)를 남기고, 상단 운영 명판에 표시합니다. 수치나 경제 없이 상태 문장만 씁니다.
- D 이상(인력 경제, 자원 관리)은 비추천합니다. Lobotomy식 경제는 CAP의 "판단 한 번의 무게"를 희석합니다.

### 5-1. 방송 선택지 재작성 예시 [제안 · DRAFT · 승인 필요]
원칙은 다음 세 가지입니다.
- 오답도 **부분적으로 맞는 근거**를 가집니다. T04는 "빛 단독은 위험이 제한적", "소리·반향이 핵심", "복합 자극이 최악"이라는 성질을 가집니다.
- 정답을 고르려면 **조합 규칙**을 이해해야 합니다.
- 길이와 어조를 통일합니다.

Q01 (직원 이동 지시) 예시 방향:
- 손전등을 끄고 벽을 짚으며 어둠 속에서 이동 → 빛은 줄였지만 벽 접촉 소음과 **개체의 상지 반경과 겹치는 벽면 경로**라는 위험.
- 손전등은 바닥만 비추고 말없이 차단 구역으로 이동 → 정답 후보(빛 단독은 제한적 위험, 발성 없음).
- 무전으로 위치를 짧게 공유하며 출구로 이동 → 소리는 작지만 **무전 잡음이 반향 복도에서 증폭**될 위험.
- 제자리에서 움직이지 말고 대기 → 자극은 최소지만 **복도 위치라면 상지 탐색 범위 안에 남음**.

이 방식은 Home Safety Hotline의 "비슷한 후보 구분"과 같은 원리입니다. 방송 기능과 구조는 그대로 두고 텍스트만 바꿉니다.

### 5-2. 결과 다양화 예시 [제안 · A]
- Q01 오답이면 결과 문서에 "복도 C-2 벽면에서 보호복 섬유와 장갑 1점 회수"처럼 해당 지시에서 나온 흔적이 남습니다. 인원 수는 쓰지 않습니다.
- Q02 오답이면 "차단문 폐쇄 지연, B구역 폐쇄 범위 확대".
- 둘 다 정답이면 "차단 구역 내 무전 응답 유지 / 명단 대조 진행 중"을 쓰되 UNKNOWN은 그대로 유지합니다.

### 6-2. 평가 [평가]
- 개체 연구와 메인 스토리를 잇는 고리가 없습니다. 지금은 Case가 "독립 퍼즐의 나열"이 될 위험이 큽니다.
- 정정, 검열, 오판 문서(ARCHIVE_02→03)는 **이미 서사 장치로 작동할 잠재력**이 있습니다. 이것을 Campaign 전체로 확장하는 것이 가장 비용이 적게 드는 서사 전략입니다.
- 강제 사건과 개체별 사고의 차이가 필요합니다. 개체 사고는 "내 판단의 결과"이고, 강제 사건은 "시설과 체제의 결과"여야 대비가 생깁니다.

### 6-3. 이야기 방향 대안 (모두 [DRAFT], 승인 전 확정 금지)

**방향 1 — "인수인계받은 연구원"**
- 플레이어는 공석이 된 담당 연구원의 자리를 이어받습니다. Story Record의 일기 6개는 전임자의 업무 일지입니다.
- 공식 Profile과 전임자 메모 사이의 **불일치**가 시설의 비밀을 드러냅니다.
- 장점: 기존 정정·검열 구조와 바로 맞물립니다. Case마다 "공식 기록이 틀렸던 이유"를 하나씩 쌓을 수 있습니다.
- 위험: 흔한 구도입니다. 전임자의 결말 설정이 핵심이 됩니다.
- 승인 필요: 전임자 존재, 공석이 된 이유, 일지의 진실성.

**방향 2 — "방송을 맡은 야간 통제원"**
- 플레이어의 핵심 책임은 연구보다 **직원 생존**입니다. 개체 연구는 사고를 예방하기 위한 업무입니다.
- 주민 명단 3개는 시설 주변 인원과 연결됩니다. Campaign 후반에는 방송의 대상이 직원에서 더 넓은 범위로 확장될 수 있습니다(대상 확장 여부는 미정).
- 장점: 방송 시스템이 서사의 중심이 됩니다. Not For Broadcast처럼 같은 시스템의 의미가 점점 무거워집니다.
- 위험: 민간인 관련 설정은 승인이 필요하며, 수위 조절이 필요합니다.

**방향 3 — "사고 기록 감사관"**
- 플레이어는 이미 일어난 사고들을 재조사하는 감사관입니다. 각 Case는 과거 격리 결정을 다시 판단하는 작업입니다.
- 사고보고서와 Historical Facts [IMPLEMENTED]가 주 무대가 됩니다.
- 장점: 기존 기록 시스템을 최대로 재사용합니다. "결과가 이미 일어났다"는 불가역성이 공포가 됩니다.
- 위험: 현재 플레이 흐름(실시간 격리 판단)과 시간 구조가 충돌합니다. 큰 방향 전환이라 비추천도 가능합니다.

**[평가] 추천:** 방향 1을 기본으로 두고 방향 2의 "방송 책임"을 결합하는 것. 기존 구현과의 충돌이 가장 적습니다.

### 6-4. 12개 Story Record의 정보 가치 [제안]

**위험 관리 [평가]**
- CCTV 효과(노이즈, 주사선)는 단서가 있는 화면에서는 약하게 유지합니다. Observation Duty 리뷰의 "필터 때문에 이상이 안 보인다"는 불만이 같은 위험입니다.
- 점프 스케어는 반복 플레이에서 가치가 급락합니다. CAP는 **정보 불일치와 침묵**이 주력이어야 합니다.

## 9. 예상 플레이타임과 콘텐츠 밀도

> **모두 추정입니다.** 실측이 아닙니다. 사람 플레이 측정이 필요합니다.

| 콘텐츠 | 상태 | 1회차 추정 |
|---|---|---|
| M2 박막낭 | TEMP, 완결 Case | 보고서 목표 10~15분(미측정) |
| M4 | M2 데이터 복제 + 다중 방송 | M2와 대부분 중복 |
| T04 | TEMP, 완결 Case | Profile 2~3분, CCTV 1~2분, 실험 3~4분, 격리 1분, 후속·사고·방송 4~6분 → **약 12~18분**으로 추정 |
| F5 기본 Campaign | 전부 TEST 자리표시 | 콘텐츠 가치 없음 |

- **현재 실제로 플레이할 가치가 있는 고유 콘텐츠: 약 25~35분**(M2 + T04). 단, 하나의 Campaign으로 이어져 있지 않습니다.
- 90~120분 목표에 필요한 것(추정):
  - 12~15분짜리 Case 6~7개(공식 9개라면 일부는 짧은 Case).
  - 강제 사건 2~3개, Story Record 12개 읽기(약 10~15분).
  - Case 사이의 업무 복귀와 지연 결과 확인.
- 밀도 위험: 모든 Case가 "Profile → CCTV → 실험 3 → 격리"의 같은 리듬이면 4번째 Case부터 반복감이 커집니다. Papers, Please처럼 **Case마다 규칙 하나가 추가**되면 완화됩니다(예: 실험 횟수 변화, 실험 장비 고장, 두 개체 동시 관찰). 이미 `experiment_limit` 같은 Case별 값이 있으므로 일부는 A로 가능합니다.

## 11. 지금 당장 개선할 상위 5개

> 전제: 아래 작업 전후로 **사람 1~3명의 T04 직접 플레이**를 권장합니다(코드 불필요). "정답을 언제 알았는가", "실험을 왜 골랐는가"를 묻습니다.

1. **T04 정보 재배분 (A)**
   - CCTV 02:00/02:40과 마지막 안내 줄, ROOM B/C 설명의 평가형 문장을 정리합니다.
   - 어두운 방(B)을 지지하는 관찰을 추가해 v0.2의 함정을 복원합니다.
   - 기대 경험: "실험해야 알 수 있다".
   - 충돌: 설정 불변, 문구만 변경(승인 필요).
2. **실험 결과 수치 + 격리 속성 값 (A)**
   - ECHO의 접촉 지속 시간과 후보별 잔향 시간을 연결합니다.
   - 기대 경험: 방음과 흡음의 차이를 플레이어가 **스스로 발견**.
   - 충돌: 수치는 신규 [DRAFT]이므로 승인 필요.
3. **방송 선택지·결과 재작성 (A)**
   - 그럴듯한 절충형 오답을 만들고, 길이를 통일하고, 흔적 조합 문장을 씁니다. UNKNOWN은 유지합니다.
   - 기대 경험: 방송이 "생각해야 하는 순간"이 됨.
4. **Archive 제목 한국어화 + 결과 읽기 패널 (A + C소)**
   - 기록을 다시 읽을 이유와 실패를 인지할 기회를 만듭니다.
5. **후속 업무를 위한 최소 "일상 업무" TEMP Case (A, 작성량 중간)**
   - 테스트 사례 01~03 대신 평범한 관찰 업무 1개를 만듭니다(개체 정식 설정 없이 "정기 점검" 성격).
   - 지연 결과, 사고, 복귀가 **진짜 업무 위에서** 일어나게 합니다.
   - 충돌: 새 TEMP 콘텐츠이며 정식 Case가 아님을 명시. 승인 필요.

1~3은 같은 파일(`temp_t04_case.tres`)의 텍스트 작업이라 **한 묶음**(가칭 M5-B.2 T04 추론 재조정)으로 진행하는 것이 효율적입니다.
