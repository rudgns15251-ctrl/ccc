# CCTV·실험 통합 화면 설계 v1 (2026-10-17 · DRAFT · 코드 변경 없음)

> 요청: CCTV와 실험을 별개 창으로 두지 말고 한 화면에서 실험을 진행하고, 진행에 따른 변화를 CCTV 화면과 텍스트로 함께 보여 준다.

## 1. 화면 구성 (1920×1080 기준 안)
```
┌ 상단 헤더: 개체 번호 · 남은 실험 n/N · 메뉴 ─────────────────────────┐
│ ┌ CCTV 모니터 (좌, 약 62%) ─────────────┐ ┌ 실험 패널 (우, 약 38%) ─┐ │
│ │ 일반 / 열화상 전환                     │ │ 실험 목록(제시 3~5개)    │ │
│ │ 영상 + OSD(CAM, 시각, 실험 중 표시)    │ │ 선택한 실험 설명         │ │
│ │ [실험 중] 영상이 실험 프레임으로 교체   │ │ [실행] 버튼 + 남은 횟수  │ │
│ └────────────────────────────────────┘ └──────────────────────┘ │
│ ┌ 관찰 기록 (하단 전체 폭) ─────────────────────────────────────┐ │
│ │ 00:00 기본 관찰문 …                                            │ │
│ │ [실험 1: 조명] 결과 문장 (실행 후에만 추가)                     │ │
│ └────────────────────────────────────────────────────────────────┘ │
└ 하단 레일: 프로필 · 관찰·실험 · 격리 ───────────────────────────────┘
```
- 720p에서는 우측 패널을 아래로 접는 세로 배치로 전환(실행 버튼은 항상 화면 안).
- 레일의 "CCTV"와 "실험"은 하나의 "관찰·실험"으로 합친다.

## 2. 실험 실행 흐름
1. 목록에서 실험 선택 → 우측에 설명과 남은 횟수, CCTV는 현재 상태 유지.
2. [실행] → 확인(이미 있는 제한 확인과 동일) → 영상이 약 1.5초 노이즈로 전환.
3. 영상이 해당 실험의 결과 프레임(`result_texture`)으로 바뀌고 OSD에 `EXP 실행 중`.
4. 하단 기록에 실험 결과 문장이 한 줄씩 나타난다. 같은 문장이 Research에 등록된다.
5. 실험 종료 후 영상은 기본 상태로 돌아가고, 직전 결과 프레임은 기록의 "다시 보기"로 남는다.
- **공개 경계 유지:** 결과 이미지와 문장은 **실행한 실험만** 공개한다. 실행 전에는 목록에 "결과 미확인"만 표시.
- **열화상:** 실험 중에도 일반/열화상 전환을 허용하면 열화상 프레임도 필요하다(Case 03). 없으면 전환 버튼을 잠근다.

## 3. 기존 구조와의 관계 (구현 전 확인 사항)
| 항목 | 현재 | 영향 |
|---|---|---|
| View | `cctv_view.gd`(141줄)와 `experiment_view.gd`(309줄)는 별개 | 통합 화면은 **표현 계층**(Presenter)에서 합성하는 안을 우선. 두 View의 시그널과 상태 복원은 유지 |
| Main의 단계 | Profile / CCTV / Experiment / Containment 4단계 | 단계 수를 유지하고 두 레일 버튼이 같은 합성 화면을 가리키게 하는 안이 가장 안전. 단계 자체를 합치려면 Main 변경이 필요 |
| 상태 복원 | `capture_work_state` / `restore_work_state` 정확 일치 | 합성 후에도 CCTV 스크롤·열화상 선택·실험 선택·결과 표시를 둘 다 저장·복원해야 함 |
| 읽기 경계 | CCTV 관찰문은 화면에 표시된 시점에 Research 해금 | 한 화면에 관찰문과 실험 기록이 함께 있으므로 "실제로 화면에 표시된 항목만" 해금하는 규칙을 유지 |
| 결과 프레임 | `result_texture`는 실험 View 안에 표시 | CCTV 모니터 영역에 같은 텍스처를 표시하도록 위치만 이동 |

## 4. 구현 순서 (제안)
1. **F6 프로토타입(T04 프리뷰 한정):** Presenter에서 CCTV 레이아웃 우측에 실험 패널을 끼워 넣는다. F5와 Main은 건드리지 않는다.
2. 1280×720과 1920×1080, 긴 한국어 문장, 큰 글자, 상태 복원, Archive 왕복을 확인한다.
3. 괜찮으면 레일을 3개로 정리하고 Case 01~03 데이터와 연결.
4. 승인 후 출시 UI를 F5로 이전할 때 함께 반영.

## 5. 미정
1. 레일을 3개로 줄일지, 4개를 유지하고 두 버튼이 같은 화면으로 가게 할지.
2. 실험 중 CCTV에 "손상 모자이크" 처리를 어디까지 적용할지.
3. 실험 결과 프레임을 정지 이미지로 둘지, 2~3프레임 짧은 연속으로 할지.

## 6. 프로토타입 결과 (2026-10-17, T04 F6 한정 · 안 A)
- **구현:** `scripts/presentation/t04_presentation.gd`에 약 150줄 추가(`_merge_experiment_monitor`, `_update_merged_monitor`, `_add_experiment_preview`). `main.gd`, F5 Scene, 다른 View는 수정하지 않았다. 되돌리기는 기존 `_undo` 경로를 따른다.
- **구성:** 두 단계가 같은 열 순서를 쓴다. `모니터 | 실험 목록 | 텍스트`.
  - CCTV 단계: 실험 목록은 **잠금 미리보기**(자물쇠 아이콘, "관찰 기록을 확인한 뒤 '다음'에서 개시합니다", 최대 횟수 표시). 오른쪽은 관찰 기록.
  - 실험 단계: 같은 위치에서 실험 목록이 활성화. 모니터는 기본 CCTV 영상이고, **실행한 실험의 결과 프레임**으로 바뀌며 OSD가 "실험 결과 / 실험명"으로 바뀐다. 오른쪽은 선택한 실험 설명과 결과 문장.
  - CCTV를 다시 보면(레일) 미리보기는 "개방됨"으로 표시.
- **권한 경계:** 결과 이미지는 기존 `ResultImage`를 모니터 안으로 옮긴 것이라 실행한 실험만 표시. 실험 전에는 기본 영상이다. Research 해금, 저장, 복원은 변경 없음.
- **스크린샷:** `docs/screenshots/merge_prototype/` (1920, 1280 각 4장).
- **검증:** 1920×1080과 1280×720에서 CCTV 잠금 미리보기, 실험 대기, 실험 결과, CCTV 재열람 확인. M5-B 경로 검사(방 A/B/C, 620개 확인) 두 해상도 실행, `verify_project.ps1` 80개 스크립트와 Main 시작 통과.
- **옛 확인 항목 2건이 실패로 표시됨(의도된 차이):** `honest_cctv`(T04에 합성 영상이 생기기 전 기준, 이전부터 알려진 항목), `video_dominant`(영상 폭이 장비 폭의 59~70%라는 M5-A 기준. 3열이 되어 영상 비중이 약 50%로 줄었으며 가장 큰 열은 여전히 영상). 필요하면 T04용 기대값으로 조정한다.
- **미검증:** 신호 깜빡임(0.55초)과 효과음은 정지 캡처로 확인하지 못했다(헤드리스에서는 소리 꺼짐). 사람의 직접 플레이 평가 0회.
- **한계:**
  - 실험 단계의 모니터에는 열화상 전환이 없다(Case 03용 기능은 후속).
  - 두 단계는 여전히 별개 View이므로, 단계를 넘어갈 때 화면이 다시 그려진다(짧은 페이드).
  - CCTV 단계에서 실험을 미리 실행할 수는 없다.
